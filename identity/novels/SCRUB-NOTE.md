# Scrub note and data note (2026-11-17)
**Scrub.** Five scripts (read-book, read-questions, tracker, wormhole, salience) and synapse/kinds.mjs had an absolute path to the author's local khora checkout as the default for `KHORA_DIR`; that default is now `path.resolve(HERE, '..', '..')` (the repo root), still overridable with `KHORA_DIR`. Nothing else was changed.
Because the FREEZE-*.md files list the sha256 of the scripts as they were when run, those six files now have different hashes; the originals are in PRE-SCRUB-HASHES.txt. Verified: the scrubbed tracker.mjs and wormhole.mjs reproduce the original outputs byte for byte on one book.
**Data not included.** Book texts, the reader's output (weft, 100+ MB), features, per-question answers and NarrativeQA's questions and answers are not committed. NarrativeQA (github.com/deepmind/narrativeqa, Apache 2.0): `documents.csv` and `qaps.csv` (see nqa-README.md and nqa-download_stories.sh). Gutenberg texts (public domain) are fetched by download-books.py and its variants (from the official mirror gutenberg.pglaf.org; the main site answered 503 on the day).
To reproduce: fetch the two CSVs, run the download-*.py scripts, then read-book.mjs, tracker.mjs, select-questions.py, read-questions.mjs and the answer/run scripts named in each FREEZE-*.md. The reader needs the khora checkout and the janus priors (KHORA_PRIORS_DIR).
**Disclosures that matter for reading the results.** All 39 test-split books in the 15-50k word window are spent; round 6 used an 8-15k window. Every set of questions was opened at most once for its preregistered test, but the same books were reused as development data in later rounds. See each RESULTS file for caveats.
